# 诗衣（Poetry Garment）

诗衣是一个完全在浏览器本地运行的 3D 诗词可视化应用。它读取 Excel 中的稀疏二维字阵，保留每个单元格的原始行列和内部空白，再把同一批字符连续卷曲、折叠为具有圆领合襟、垂展袍袖、束带收腰与长袍垂摆的明制圆领袍。

项目内置 `深秋织锦.xlsx` 作为启动示例，也支持用户上传 `.xlsx` 和 `.xls` 文件。Excel 不会上传到服务器。

## 环境与启动

- Node.js 20.19+（本项目在 Node.js 24.20 下验证）
- 支持 WebGL 的现代 Chrome、Edge、Firefox 或 Safari

```bash
npm install
npm run dev
```

打开终端输出的本地地址，通常为 `http://localhost:5173`。

其他命令：

```bash
npm test          # 运行解析、字素、映射和动画单元测试
npm run build     # TypeScript 检查并生成生产构建
npm run preview   # 本地预览 dist 生产构建
```

可选的浏览器验收脚本需要先在另一个终端运行 `npm run preview -- --port 5174`，再执行 `npm run qa:browser`。它会使用系统 Chrome/Edge 检查示例指标、生成/暂停/重播、最终视角与控制台错误，并把截图写入已忽略的 `qa/`。可用 `BROWSER_EXECUTABLE_PATH` 和 `QA_BASE_URL` 覆盖默认值。

## GitHub Pages 部署

项目已配置 `.github/workflows/deploy-pages.yml`：推送到 `main` 后，会自动安装依赖、运行测试、构建并部署 `dist/`。

1. 将项目上传到 GitHub 仓库，默认分支使用 `main`。
2. 打开仓库的 **Settings → Pages → Build and deployment**，将 **Source** 设为 **GitHub Actions**。
3. 在 **Actions** 中运行 **Deploy to GitHub Pages**，或再次推送到 `main`。
4. 部署成功后，在工作流的 `github-pages` 环境中打开网站链接。通常为 `https://<用户名>.github.io/<仓库名>/`。

Vite 使用相对资源路径，因此仓库名称变化时无需修改配置；内置 Excel 示例会一起打包。只需提交源码和 `package-lock.json`，`node_modules/`、`dist/` 和本地验收产物已忽略。

## 使用方式

1. 页面会自动载入《深秋织锦》示例，或点击上传区选择自己的 Excel。
2. 检查左栏的字符数、空白槽位及异常提示。
3. 点击“生成诗衣”播放完整的 12 秒动画。
4. 动画完成后，用左键旋转、滚轮缩放、右键平移；“重置视角”恢复相机。
5. 点击重播按钮或“再次生成”即可从二维原阵重新开始，无需刷新页面。
6. 底部进度条可直接定位任意阶段；所有姿态都由统一进度重建。

## Excel 约定

- 每个有效单元格应包含一个 Unicode 字素，例如一个汉字、扩展区汉字或标点。
- 应用读取工作表 `!ref` 的绝对范围，并用单元格坐标保留空白间距；不会先把内容拼成字符串。
- 稳定 ID 采用 `工作表!R行C列`，重复汉字仍是不同实例。
- 含两个可见字素的单元格会阻断生成，并显示 A1 坐标。
- 若一个单元格仅因首尾空格或换行形成多个字素，应用会明确提示坐标、保留原始值用于审计，并用唯一可见字素渲染。内置示例的 `DF53` 即为“落”后带换行。
- 多工作表文件可在字阵结构区切换工作表。
- 安全上限为 20 MB、500,000 个网格槽位和 20,000 个有效字符，防止异常工作簿占满内存。

## 动画时间线

| 时间 | 阶段 | 行为 |
| --- | --- | --- |
| 0–2 秒 | 原阵 | 字符保持 Excel 的二维行列，Z=0 |
| 2–5 秒 | 卷曲 | 平面围绕纵轴连续卷曲，字符位置与旋转同步变化 |
| 5–9 秒 | 织形 | 字符从卷面折展到服装参数曲面 |
| 9–12 秒 | 成衣 | 字符保持最终姿态，相机缓慢环绕 |

着色器使用平滑的五次缓动函数。动画从不可变的起点、卷曲点和目标点计算，不累计上一帧变换，因此暂停、拖动和重播不会漂移。

## 关键实现

### Excel 与字符守恒

`src/services/excel.ts` 使用 SheetJS 的稀疏工作表对象按绝对地址读取单元格。`Intl.Segmenter` 负责 Unicode 字素边界；解析结果同时保留 `rawValue`、可见字形、行列、A1 地址和稳定 ID。生成前后实例数量与 ID 不变。

### 参数化服装

`src/geometry/garmentMapping.ts` 将行归一化为衣长，将列映射到前后环绕曲面。曲面包含：

- 前后身椭圆截面
- 圆领合襟与平直肩线
- 两侧袍袖自然下垂展开
- 腰带束身与长袍垂摆
- 由有限差分切线和法线生成的目标四元数

字符平面会贴合局部曲面方向，不使用始终朝向相机的 billboard。

### 人形上身：线稿圆领袍

`src/geometry/humanFigureMapping.ts` 把同一件明制圆领袍穿到人身上，对应界面的“人形上身”样式。曲面的纵向控制点直接取自参考线稿的比例，因此改动输入表格的行数不会改变头肩比：

- `幞头` 圆顶带一道横向巾带，下方是无五官的空白面容与短颈，人物身上只留输入的字。
- `圆领` 为前置的双线滚边，向前中下沉成 U 形，领口内侧随之凹陷，字形的法线与可见领脊一致。
- 两袖分别向左右展开：左袖抬肘前伸、腕后垂落宽大的琵琶袖并收成拳；右袖屈肘下垂，手落在腰带右侧。
- `腰带` 抬升成带状，前身以 20 段波峰分出带銙，中部另有一枚带扣。
- 长摆自腰带向下张开，前身用 `cos(localX · 9.2)` 折出褶裥，中缝是一道凹槽。

`src/rendering/robeGuides.ts` 用同一条曲面采样绘制结构线，因此领缘、带銙分隔、褶裥折痕与双履的轮廓都与文字落在同一折面上；褶线由 `humanFigurePleatPosition` 反解出参数坐标后再取样，而非另画一条近似曲线。

### GPU 字形渲染

`src/rendering/glyphAtlas.ts` 把唯一字形一次绘制到 Canvas 图集；重复字符复用 UV，但仍保留独立实例。`InstancedBufferGeometry` 为每个字符上传起点、目标点、目标旋转、UV、颜色和尺寸。每帧只更新一个 `uProgress` uniform，顶点着色器完成卷曲与折叠。

内置示例包含 2,097 个字符和 730 个可见唯一字形，使用一页 2048×2048 图集，因此文字主体只有 1 个 draw call。2,449 条四邻接经纬线合并为另 1 个 `LineSegments` draw call；跨服装分区的过长连线会在成衣阶段淡出。

### 本地样例基线

- 工作表：`Sheet1`
- 有效范围：`AC37:DO138`
- 网格：102 行 × 91 列
- 有效单元格：2,097
- 内部空白：7,185
- 四邻接连线：2,449
- 唯一输入异常：`DF53="落\n"`，会显示可见归一化警告

## 项目结构

```text
src/
  animation/       统一时间线、缓动和可重建姿态
  components/      上传、校验、时间线和错误边界
  geometry/        服装参数曲面、区域和字符映射
  hooks/           播放控制器
  rendering/       字形图集、GPU 缓冲与 GLSL 着色器
  scene/           R3F 场景、相机与 OrbitControls
  services/        Excel 读取与验证
  types/           字阵和校验数据契约
  utils/           Unicode 字素工具
```

## 视觉与兼容说明

- UI 使用米白、墨黑和淡金色；字体优先调用系统行楷、楷体和 CJK Serif 回退。
- 生僻字能否呈现取决于操作系统字体覆盖；缺字时浏览器会继续使用字体栈回退。
- WebGL 不可用时，界面会保留并显示明确错误，不会让整页空白。
- 文字和经纬线是服装的主要可见表面，没有不透明布料网格遮挡字符。

## 验证

自动测试覆盖：

- 中文标点、扩展汉字、组合字符与换行字素
- 稀疏网格空白与绝对坐标
- 多可见字素阻断及尾随换行提示
- 示例文件 2,097 字符、7,185 空白和 2,449 条边基线
- 目标坐标有限、四元数归一和字符数量守恒
- 人形上身：幞头/面容/短颈分区、圆领 U 形对称下沉、袍袖外展下垂、腰带连续、长摆对称张开与褶线反解
- 0、2、5、9、12 秒边界及同进度重复采样一致性
- 恶意超大 `!ref` 在扫描前被拒绝
